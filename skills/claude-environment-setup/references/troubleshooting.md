# 故障处理

先看现有状态，不先重装或退出账号。所有设置修改都先备份；排障结论只覆盖实际检查范围。

## 关闭旧代理后全部断线

1. 核对系统代理、应用显式代理地址、端口监听者与 Clash 核心。
2. 新旧客户端不能同时争用同一端口。改到独立端口后，还要同步系统代理与应用环境。
3. 先确认新核心的真实请求，再退出旧客户端复验；旧客户端仍运行时成功不代表新客户端可独立工作。
4. 若当前聊天依赖代理，把可能断线的切换交给用户，并提前说清恢复步骤。

历史曾出现：efan 占用 7897、Clash 临时 7896、Codex 仍找 7897。数字仅用于说明问题，不应硬编码为别的设备配置。

## 节点全红或控制接口可访问但行为异常

先确认核心是否持续运行，控制接口由哪个进程监听。不要把 Docker 等其他服务的响应当 Clash。节点独立测试可用，和 GUI 当前测速正常是两个证据。

签名检查受沙箱限制时，先明确权限边界；不要直接推断整个应用损坏。架构不匹配、helper 服务、日志与端口冲突分开处理。下载/更新客户端时核对官方发布包及校验信息，保留订阅和私有扩展。

## 住宅新开通后连接超时

检查供应商线路状态、服务器/端口、认证、前置连通、`dialer-proxy` 引用和循环引用。允许有限复测并保留可用网络，不反复切换全机配置。历史超时随后恢复，“初始化未完成”只是当时可能解释，没有被证实。

## 网页登录成功，CLI 仍使用 MiniMax

1. 检查 `type -a claude` 与实际新进程的版本，避免旧 Volta 入口。
2. 先备份 `~/.claude/settings.json`，检查配置和进程环境中的 provider/模型覆盖。
3. 重点是 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL`、默认模型映射、`ANTHROPIC_MODEL` 和 `ANTHROPIC_REASONING_MODEL`。只读取是否存在/字段名称，日志不要带值。
4. 若目标明确为官方订阅，只处理相关旧覆盖，保留 MCP、插件、Hooks 等其他配置。
5. 重开进程，再检查认证/provider 和最小实际请求。

不要因沙箱读取 macOS 钥匙串失败而认定已退出登录，更不要自动删除认证来“修复”。

## 手机读屏正常，右侧或底部点击失败

先比较返回的屏幕尺寸与实际设备。历史 iPhone Use runner 将屏幕误报为 320×480。只有定位到相同根因，才考虑备份代码、优先用前台应用 frame 获取尺寸、重建部署；不要对未知版本盲套补丁。

构建成功、USB 连接、`drivable=true` 和真正完成点击是不同阶段。只读沙箱无法访问本机服务，不等于主控制通道失效。

## 到期后 Mac 可用，专用浏览器或手机仍失败

三处入口分开检查：Mac 的目标代理组、浏览器固定 SOCKS5 入口的实际绑定、手机选中节点。只改 Mac 组，可能遗漏浏览器固定住宅监听和手机旧节点。

## 账号或购买状态缺证据

邮箱以收件箱为准；Claude 以正确账号的实际回复为准；CLI 以认证及实际模型请求为准；交易以订单/收据为准。没有证据时保留未核实，不从其他环节补推。
